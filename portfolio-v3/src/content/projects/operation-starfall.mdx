# Operation Starfall

My work focused on both gameplay programming and visual systems,
including a ground-based enemy with state-driven AI and a shader-driven stamina system.

---

## Overview

I worked together with another developer to extend an existing Unity codebase with new gameplay and visual features.

Rather than building systems from scratch,
much of the work involved understanding and extending existing systems such as the ForceSystem,
enemy AI and state machine architecture.

Two features I contributed to were **Octodrone**,
a ground-based enemy with patrol, detection and attack behavior, and **Radial Stamina**,
a shader-driven stamina display built with ShaderGraph.

---

## Octodrone

Octodrone was the first ground-based enemy developed for Operation Starfall.

The feature combined state-driven AI, animation cycles and attack behavior.
Existing patrol and detection systems had originally been built around flying enemies,
so we adapted and extended this logic to support grounded movement.

### Gameplay & AI

Through pair programming,
we refactored the existing enemy behavior to support reliable ground patrols,
detection and directional movement.

Octodrone's state machine controls states including:

- Patrol
- Detect
- Jump / Attack
- Fuzzy

The Animator was connected to these states using animation triggers and Unity Events, allowing transitions such as:

`JumpUp → JumpTop → JumpAttack`

### Implementation

One of the more interesting parts of the feature was working with the existing ForceSystem.

The system controlled much of the movement behavior in the existing codebase, so understanding how forces interacted with the enemy state machine was an important part of getting Octodrone working reliably.

## Radial Stamina

Radial Stamina replaced the old stamina system in Operation Starfall.

This feature was built collaboratively with another developer and became my first hands-on shader project using ShaderGraph.

### From Gameplay to Visuals

Instead of representing stamina through a conventional UI bar, we created a radial display inspired by the stamina system in *The Legend of Zelda: Breath of the Wild*.

The system combines gameplay state with a shader-driven visual representation:

- stamina percentage controls the radial fill
- gameplay events control visibility
- time-based logic handles fading
- a radial mask defines the shape of the ring

[//]: # (<!-- Radial stamina GIF -->)

### ShaderGraph

The shader is divided into three main parts:

**Fade Logic**
Controls when the stamina radial appears and fades away after a stamina update.

**Texture Logic**
Combines the radial texture with its color.

**Shape Logic**
Uses a radial mask and stamina percentage to determine how much of the ring is visible.

## Collaboration & Process

Both features were developed collaboratively through pair programming.

Working inside an existing codebase meant that a significant part of the development process involved understanding systems that had already been established by the team.

For Octodrone, this meant learning how the existing ForceSystem and enemy architecture interacted before extending it for ground-based behavior.

For Radial Stamina, it meant stepping outside of my usual code-focused workflow and learning how gameplay data could drive a visual system through ShaderGraph.

---

## Takeaway

Operation Starfall gave me experience working inside a larger existing Unity codebase while contributing to both gameplay and visual systems.

Octodrone strengthened my understanding of state-driven gameplay, animation integration and working with existing systems. Radial Stamina introduced me to ShaderGraph and showed me how shaders can become part of gameplay features rather than purely visual effects.

Together, the two features represent the two sides of my work I enjoy most: **building gameplay systems and using graphics to give them a stronger visual identity.**
