## Overview

Acerola's Dirt Jam is a community event encouraging participants to explore graphics and shader programming.
For this project, I started with the provided reference code and a list of suggested ideas to experiment with.

## Creative Direction

<Split ratio="1:1">
    <div>
        The visual direction started with Kankan's `Way2Geeked` album visualizer,
        particularly in combination with the song `Livefastdieslay ##4Kaine`.
        I was drawn to its noisy, high-contrast imagery, shifting between washed-out grays and saturated pinks.
        I initially considered recreating some of these visuals through shader effects,
        but eventually decided to take the elements I liked and reinterpret them in a different context.
    </div>
    <div>

        including SoFaygo's `Pink Heartz` and LUCKI's `s*x m*ney dr*gs`,
        helped shape the direction further. I collected these references into a moodboard, using their colors,
        textures and abstract imagery as a starting point for the environment.

## Getting Familiar

<Split ratio="1:1">
    <div>
        Before jumping into new features, I first wanted to understand what I was working with.
        The jam provided an annotated terrain generator in Godot,
        so I went through the code and experimented with the available inspector parameters.
    </div>
    <div>
        I played around with the mesh settings, noise generation,
        octave count and material properties to get a better understanding of how they influenced the generated terrain.
        This gave me a starting point for deciding what I wanted to build on top of the existing implementation.
    </div>
</Split>

<Split ratio="1:1" reverse>
    <div>
        The jam also provided a list of suggested features for participants looking for ideas.
        After considering which ones were most relevant to my plans,
        I settled on four to start with:

        - **Distance Fog** - introducing atmospheric depth.
        - **Shader Include Files** - reducing duplicated code between shader stages.
        - **Level of Detail** - adjusting terrain detail based on camera distance.
        - **Improved Lighting** - extending the existing Lambertian model with specular highlights.
    </div>

## Building Atmosphere

<Split ratio="1:1">
    <div>
        With the initial features implemented,
        I started bringing them together in an early scene mock-up.
        I experimented with different post-processing combinations,
        comparing screen-space and additive bloom before settling on the latter.
    </div>
    <div>
        `Distance fog` became a more involved exploration.
        Linear fog was relatively straightforward to implement,
        which gave me the confidence to push it further with exponential fog.
        That proved considerably more challenging and led me to investigate the underlying attenuation theory,
        eventually discovering `Beer's Law` through discussions in the jam community.
    </div>
</Split>

## Texture Mapping

<Split ratio="1:1">
    <div>
        Moving beyond the terrain's initial flat coloring,
        I wanted to introduce actual surface textures.
        This turned out to be the most challenging part of the project.
        Getting triplanar texturing to work without unwanted stretching took several days of debugging.
    </div>
    <div>
        I was struggling to get the textures and their associated resources to work correctly,
        so I reached out to other jam participants.
        `Refoulay` shared their implementation, which gave me a useful reference for troubleshooting my own.
        After working through the initialization and texture-binding issues,
        I eventually got the terrain rendering correctly.
        I then extended the implementation to support different texture resolutions,
        testing everything from 128px to 4K in the running scene.
    </div>
</Split>

## Post Mortem

<Split ratio="1:1">
    <div>
        This project was my crash course into graphics programming.
        Along the way, I got familiar with concepts such as:

        - GPU Data Alignment
        - Procedural Terrain Generation
        - Terrain Rendering
        - Compositor Effects (Godot)
        - Vulkan and SPIR-V
    </div>
    <div>
        My favorite takeaway was figuring out GPU memory alignment -
        and coming up with my own analogy to really understand it:

        > Think of UBO memory like an inventory grid.
        > Each row can hold 4 slots, but different data types have their own placement rules.
        > Bigger items like `vec3` and `vec4` need VIP spots at the start of a row.
        > A `vec3` leaves one slot available for a `float`,
        > while a `vec2` needs to start at an even slot.
        >
        > You can't just put things wherever there's an empty space.
        > If you change the order on the CPU side,
        > you have to rearrange the layout to match what the GPU expects.
    </div>  
</Split>
