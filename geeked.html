Intro

Way2Terrain began as an entry for the Dirt Jam. I debated using Unity or Godot, but went with Godot — it’s the recommended FOSS option, and the reference code was already written for it by Acerola, complete with helpful comments.

I had two concept ideas:
1) Way2Geeked — cloud rap vibes, experimental, geeked out.

2) Hueco Mundo but I’m already tackling that in another Unity project, so I shelved it.

Naturally, I went with Way2Geeked and built this moodboard to lock in the aesthetic. The spark came while I was listening to music and stumbled across the “Way2Geeked” visualizer on YouTube. All I could say 'bout it: “this shit trim, luh twin.”

Development

Way2Terrain came together by diving headfirst into topics I’d never touched before. Engines like Unity and Unreal have luxuries like built-in shader includes, auto shader recompilation, and polished terrain systems. Godot… doesn’t — which meant I had to learn exactly what was happening under the hood.


Technical Challenges

  • • GPU Data Alignment – Learned that forgetting to pad a struct for 16-byte alignment can turn your shader uniforms into nonsense. GPUs read in vec4 chunks, so a vec3 needs a dummy float to keep the layout intact.

    • Shader Modularity – Built a GDScript-driven GLSL include loader, cutting ~500 lines of duplicated shader code.

    • Texturing – After 7 restarts and 5 days of trial and error, achieved clean triplanar mapping, supporting textures from all sizes mixed and matched.

    • Water Shader – Vertex-based displacement with Fresnel reflections, integrated into Sky3D.

    • Fog & Lighting – Swapping to exponential fog revealed a blend issue where lit terrain flattened into the fog color. Lighting also got a Blinn–Phong upgrade for sharper highlights.

Conclusion

Way2Terrain became both a technical playground and a creative statement — proof that a game engine can be as much about expression as simulation. The journey wasn’t without heartbreak: I missed the official submission deadline thanks to an incomplete itch.io page and a broken build. FOMO hit hard… until I saw the final submission count: 69 ENTRIES (worth it)

On the bright side, I learned a lot about core low-level rendering concepts — from custom render pipelines and Vulkan’s API, to compositor effects, uniforms, buffers, and alignment. While struggling with that last one, I came up with an analogy:

“Think of UBO memory like an inventory grid. Each data type has its own slot size, and a row can only hold 4 slots. Bigger items (like vec3 and vec4) get VIP spots at the start of the row, and smaller items fill in the gaps. If the order changes on the CPU side, you have to re-pack the layout to match on the GPU side.”

Safe to say WE all understand alignment now.
